# VirasoroProject improvement analysis and implementation report

*Date: 2026-07-11/12. Baseline: commit `f1b6807` (Lean `v4.32.0-rc1`, Mathlib `052559c`).
Final state: full `lake build` with **0 errors and 0 warnings** (baseline had 26 warnings);
`checkdecls` passes for all 44 blueprint-referenced declarations; every `ToMathlib/` file
is compiled as part of the root module.*

This report analyzes how the formalization could be improved — design, structure,
maintainability against toolchain bumps, and proof readability (with a preference for
`calc` blocks) — and records what was implemented. The comparison repository
`/opt/HL/MLP/MyLeanPlay/` (fermionic Sugawara constructions, Ramond and Neveu-Schwarz
sectors) served as the exemplar: those files are written against current Mathlib idioms
and are markedly more robust and readable than the bosonic `Sugawara.lean` was.

Per instructions, the Lie-cocycle/central-extension development
(`LieCohomologySmallDegree.lean`, `CentralExtension.lean`, `IsCentralExtension.lean`,
`SectionSES.lean`) is kept as-is; only two mechanical linter items were fixed there (B7).

**Status legend:** ✅ implemented · 🔶 partially implemented · 💡 proposed, not implemented.

## A. The Sugawara construction (`Sugawara.lean`, `CentralChargeCalc.lean`)

This is where the gap to the exemplar was largest. The fermionic files prove the same
shape of theorem via a chain of focused lemmas, each with a `calc` skeleton, while the
bosonic file proved it in one ~175-line monolith (`commutator_sugawaraGen`) with five
levels of nested `by_cases`, `Finset.sum_of_injOn` reindexing through `toNat`/`natAbs`,
and side conditions interleaved with the main argument. `Sugawara.lean` went from
838 to 726 lines while gaining several new statements; the proofs are now structured.

### A1. ✅ Adopt `Function.HasFiniteSupport` and its combinator API

Mathlib (2026, M. Stoll) has `Function.HasFiniteSupport f := f.support.Finite` with
combinators (`.smul_right`, `.add`, `.neg`, `.fun_comp`, …), and the `finsum`
interchange lemmas (`finsum_add_distrib`, `finsum_sub_distrib`, `smul_finsum'`,
`finsum_smul'`) take it directly. The eight from-scratch `finite_support_*` lemmas are
replaced by **one** support lemma `hasFiniteSupport_pairNO_apply` (general index
pattern `(n−k, m+k)`, following the Ramond file) and seven one-line corollaries via
combinators and `heiOper_pairNO_eq_pairNO'`. The blueprint reference was renamed
(`finite_support_smul_pairNO_heiOper_apply` → `hasFiniteSupport_smul_pairNO_apply`)
and `blueprint/src/chapters/sugawara.tex` updated.

### A2. ✅ Normal-form lemma: normal-ordered pair = raw product − boundary·1

The single most consequential structural idea in the fermionic files
(`ferPairNO_eq_sub_smul_one_sign`) now has a bosonic counterpart,
`pairNO'_eq_mul_sub_boundary`:

```
:J k J l:' = J k * J l − (if 0 ≤ k ∧ k + l = 0 then (k : 𝕜) else 0) • 1
```

Since the boundary term is central, every commutator computation happens on raw
products, where `LinearMap.commutator_pair'` applies. The previous
`commutator_sugawaraGen_heiPairNO'` proof — a 65-line four-way sign case split
re-deriving the commutation relation inside each branch — is replaced by:
`commutator_sugawaraGen_mul` (`[Lₙ, J k · J l]`, three lines from
`commutator_pair'`), then converting products back via A2 and comparing scalars
with `match_scalars` (the tactic the Ramond file uses for the same step).

### A3. ✅ Restate `commutator_sugawaraGen_heiPairNO'` cleanly — and fix a blueprint erratum

The old Lean statement carried its boundary terms *inside* a `-k •` scalar action,
forcing every consumer to redistribute them. The new statement has the normal-ordered
part with plain coefficients plus a single boundary summand:

```
[L n, :J (m−k) J k:'] = −k • :J (m−k) J (n+k):' − (m−k) • :J (n+m−k) J k:'
                        + (δ[n+m=0] · k(n+k)(δ[k+n≤0] − δ[k≤0])) • 1
```

While reshaping this, a genuine **erratum in the blueprint** surfaced: the TeX stated
the boundary as `(n+k) δ_{n+m,0} (𝟙[−n≤k<0] − 𝟙[0≤k<−n])`, which has a missing factor
`k` and the opposite sign (checked against the machine-verified formula and by a hand
computation of `[L₋₂, :J₁J₁:]`). The TeX statement and its proof sketch were corrected
to the machine-checked form.

### A4. ✅ Split the main proof into the fermionic file's structure

`commutator_sugawaraGen` is now assembled from:

1. `commutator_sugawaraGen_apply_eq_finsum_commutator_apply` (blueprint name kept) and
   its flipped variant — the commutator/finsum interchange, now `calc` blocks with the
   two `HasFiniteSupport` facts named up front (Ramond pattern).
2. `commutator_sugawaraGen_heiPairNO'` (A3).
3. `sugawaraGen_NO_sum` (new, `private`) — the telescoping
   `∑ᶠ k (−k·NO₁ + (k−m)·NO₂) = (n−m) • ∑ᶠ NO`, a commented `calc` with the index
   shift by `finsum_comp_equiv (Equiv.subRight n)` and side conditions collected
   after the `calc`. (The bosonic case is *simpler* than the fermionic one here: the
   combined coefficient is already the constant `n − m`, so no vanishing-sum lemma is
   needed.)
4. `ccTermInt` + `hasFiniteSupport_ccTermInt` + `sugawaraGen_cc_sum` (new, `private`)
   — the central-charge sum in closed form via `sum_Ico_quadratic` (A5), covering
   both sign regimes without `toNat`/`natAbs` reindexing. The boundary coefficient
   `k(n+k)` vanishes at both interval endpoints, so no endpoint splitting is needed
   (again simpler than the fermionic analogue).
5. The main theorem: a five-step commented `calc` (expand, commute past pairs, split
   NO/central parts, evaluate each).

The `smul_cancel_of_non_zero_divisor`-by-2 trick with its `(by aesop)` argument, the
anonymous `⟨fun k ↦ k − n, …⟩` equivalences, and the `Finset.sum_of_injOn`
reindexings are gone. Statement-level change: the coefficients in
`commutator_sugawaraGen_heiOper` and `commutator_sugawaraGen` are now `𝕜`-valued
(`-(m : 𝕜) •`, `((n : 𝕜) - m) •`) instead of `ℤ`-scalar actions, eliminating a layer
of `Int.cast_smul_eq_zsmul` conversions throughout (the blueprint statements are
agnostic to this).

Dead code discovered and removed while restructuring: the never-used truncation trio
`heiPairNO_trunc_atTop_sub`/`_atBot_sub`/`_cofinite_sub`,
`sugawaraGen_apply_eq_finsum_shift`, `sugawaraGenAux_comp_apply`; and
`commutator_sugawaraGen_heiOperPair` / `commutator_sugawaraGen_heiPairNO'_apply` are
superseded by the new lemmas.

### A5. ✅ Replace the `zPrimitive` machinery by Gauss-sum closed forms

`CentralChargeCalc.lean` (234 lines) built a discrete-integration theory
(`zPrimitive`, `zMonomialF` with evaluation lemmas at degrees 0–5 and a
factorial-product formula) to evaluate one quadratic sum. It is rewritten (109 lines)
with the three MyLeanPlay `GaussSums` lemmas — `sum_Ico_id`, `sum_Ico_sq`,
`sum_Ico_quadratic` over `Finset.Ico a b`, `a b : ℤ` — valid in both sign regimes,
which is exactly what the central-charge computation consumes. The blueprint-pinned
`bosonic_sugawara_cc_calc_nonneg` is kept with its exact statement, proved by a short
self-contained induction `calc` (matching the blueprint's proof sketch, "Calculation
(with induction)").

### A6. ✅ Make `representationOfCentralChargeOfL` bump-proof

The definition used a tactic-mode `let ops := fun n' ↦ match n' with …`; the companion
lemmas had to reconstruct that match-term verbatim inside `show`/`convert` — precisely
what broke during the toolchain bump. Now:

* the operator family is `fun i ↦ i.elim (c • 1) lOper` (no match syntax to
  reconstruct), and the definition is a term-mode application of
  `LieAlgebra.representationOfBasis`;
* new `@[simp]` lemma `LieAlgebra.representationOfBasis_apply_basis` (in
  `LieAlgebraRepresentationOfBasis.lean`), from which
  `representationOfCentralChargeOfL_cgen`/`_lgen` (now `@[simp]`) are two-liners;
* the commutation-relation glue is a named `private` lemma `sugawaraGen_lComm`, so
  `sugawaraRepresentation` is a plain term-mode definition and its API
  (`sugawaraRepresentation_cgen`, new `sugawaraRepresentation_lgen`,
  `…_lgen_apply'`, `…_lgen_apply`) follows by `exact`-level defeq — no `unfold`, no
  `convert ..`;
* `FockSpaceSugawara.lean`'s consumers were rewritten accordingly: the `let`-based
  definition (which caused a `whnf` timeout when unfolded) is inlined, and the
  `unfold …; simpa/convert` repairs are replaced by direct term applications
  (`LinearMap.congr_fun key v` etc.).

### A7. ✅ Stop using the project-local `LinearMap.map_finsum`

`ToMathlib/Topology/Algebra/Module/LinearMap/Defs.lean` existed to provide
`LinearMap.map_finsum`; this has been **incorporated into Mathlib** in generalized form
(`map_finsum`, for any `AddMonoidHomClass` map — which also settles the generalization
TODO the original carried). `Sugawara.lean` now uses Mathlib's `map_finsum` directly;
the ledger file records the incorporation and keeps the original statement as a
`@[deprecated map_finsum]` alias (see B2). A related discovery: the sibling file
`ToMathlib/Topology/Algebra/BigOperators/FinProd.lean` is *live* — its
`finsum_add_finsum_compl` is used by `sugawaraRepresentation_lgen_apply` (it had been
reachable only through this file's import); `Sugawara.lean` now imports it directly.

### A8. 💡 Not done: unify `pairNO`/`pairNO'` into a single definition

Both names are blueprint-pinned and the two-definition design isolates where `heiComm`
is genuinely needed; left alone deliberately.

## B. Repository-wide improvements

### B1. ✅ Sync `Commutator.lean` with the MyLeanPlay superset

The file is now textually identical to MyLeanPlay's (adds `add_commutator`,
`commutator_add`, `smul_commutator`, `commutator_smul`; the `@[simp]`
`commutator_smul_one`/`smul_one_commutator` are used by the new A2/A3 proofs).
Keeping shared files identical also makes future cross-repo diffing trivial.

### B2. ✅ Curate `ToMathlib/` as a Mathlib API-gap ledger

`ToMathlib/` is deliberately a record of observed Mathlib API gaps (upstreaming
candidates), so files there are **kept even when unused by the main development**.
(An earlier iteration of this work deleted five unreachable files; they were restored
and improved instead.) Each file now has a copyright header, a module docstring, and
an explicit *upstream status* note checked against the pinned Mathlib (`052559c`):

* `LinearAlgebra/Finsupp/Supported.lean` — `finsum_mem_span`, `finsum_mem_mem_span`:
  **still missing from Mathlib**. Made the canonical home of these lemmas: the
  textual duplicates in `FinsumRepr.lean` (which had drifted — only that copy was
  repaired during the bump, the ledger copy had rotted) were removed in favor of an
  import. Its own `-- TODO: Golf.` is resolved: `finsum_mem_mem_span` went from 23
  lines to 4 (restrict to the subtype via `finsum_set_coe_eq_finsum_mem`, apply
  `finsum_mem_span`, transport the span along `Set.range ↪ image`).
* `Topology/Algebra/Module/LinearMap/Defs.lean` — `LinearMap.map_finsum`:
  **incorporated into Mathlib** as `map_finsum` (more general). Kept as a
  `@[deprecated map_finsum (since := "2026-07-12")]` alias documenting the original
  statement and its upstream replacement.
* `Topology/Algebra/InfiniteSum/Basic.lean` —
  `DiscreteTopology.summable_iff_eventually_zero`: **incorporated in substance**
  (`Summable.hasFiniteSupport_of_discreteTopology` and
  `summable_of_hasFiniteSupport`); only the packaged iff in `Filter.cofinite`
  phrasing remains a candidate. Proof golfed from 15 lines to 2 using the
  incorporated halves; a spurious `[DecidableEq ι]` hypothesis dropped.
* `Topology/Order.lean` — `DiscreteTopology.tendsto_nhds_iff_eventually_eq`: not
  packaged in Mathlib, but now a one-line combination of the Mathlib lemmas
  `nhds_discrete` and `tendsto_pure` (proof golfed accordingly).
* `Topology/Algebra/ConstMulAction.lean` —
  `continuousConstSMul_of_discreteTopology`: **still a genuine gap** (Mathlib has no
  `DiscreteTopology`-based `ContinuousConstSMul` instance). A spurious
  `[AddCommMonoid X]` hypothesis was dropped, the `def … := ⟨fun c ↦ by continuity⟩`
  became `lemma … := ⟨fun _ ↦ continuous_of_discreteTopology⟩`, and a note explains
  it stays a `lemma` (not an `instance`) pending an upstream priority decision.
* `Topology/Algebra/BigOperators/FinProd.lean` — live (used by `Sugawara.lean`, see
  A7); header plus the naming-inconsistency notes (`finsum_add_distrib` vs
  `finsum_add` etc.) worth raising when upstreaming.

To prevent future rot, **all ten `ToMathlib` modules are now imported from the root
`VirasoroProject.lean`**, so `lake build` compiles the ledger alongside the main
development. The root also imports `CentralChargeCalc` and `Commutator` explicitly,
so every file in the repository is reachable from the root module.

### B3. ✅ Golf the bump-repair scars

Each recognizable scar from commit `f1b6807` is replaced by an honest proof:

* **`all_goals first | rfl | simp […] | simp […]`** (with a duplicated branch) in the
  cartan-basis lemmas of `FockSpace.lean` / `VirasoroVerma.lean` — now
  `Subtype.ext` + the `@[simp]` lemma `basis_submodule_span_apply` + `rwa`, three
  honest lines each. The `⟨some 0, by exact …⟩` term-in-statement scars are plain
  terms again.
* **`apply ext' <;> simp […] <;> rfl`** in `HeisenbergAlgebra.lie_jgen` /
  `VirasoroAlgebra.lgen_bracket` — root cause was *missing component API*: the files
  had `add_fst/add_snd/smul_fst/smul_snd` but no `zero_fst/zero_snd` and no component
  lemmas for the generators. Added `@[simp]` lemmas `zero_fst`, `zero_snd`,
  `jgen_fst`, `jgen_snd`, `kgen_fst`, `kgen_snd` (resp. `lgen_fst`, `lgen_snd`,
  `cgen_fst`, `cgen_snd`), after which both bracket lemmas are three-line
  `by_cases <;> apply ext' <;> simp [...]` proofs. (This is the mathlib-review
  guideline in action: needing `rfl` after `simp` means the API is missing lemmas.)
* **`unfold sugawaraRepresentation…` + `convert ..`** in `Sugawara.lean` /
  `FockSpaceSugawara.lean` — eliminated by A6.
* **`:= by exact …`** wrappers on `toAbelianLieAlgebraOn`, `ofCentral`,
  `toWittAlgebra` — removed; the plain terms elaborate (the bump-era wrapper was a
  shotgun fix, not actually needed once the files' local `LieRing.ofAssociativeRing`
  instance was in place).
* **Stray `example … := by exact β.flip`** (leftover scratch) in
  `HeisenbergAlgebra.lean` — deleted.
* **`-- `calcify`?` `rw`-chain** in `ChargedFockSpace.eventually_jgen_smul_eq_zero` —
  now the four-step `calc` the comment asked for
  (`J_k • v = (J_k a) • Ω = (a J_k) • Ω = a • 0 = 0`).
* **Deprecated identifiers** (`Finsupp.finite_support`,
  `finsum_eq_finset_sum_of_support_subset`, `Finsupp.coe_finset_sum`) in
  `FinsumRepr.lean` / `LieVerma.lean` — renamed to current Mathlib names.

Two scars were deliberately **kept**:
`FockSpaceSugawara.commutator_lsmul_jgen_…`'s closing
`convert key v using 1; all_goals first | rfl | (by_cases … <;> simp […] <;> rfl)` —
a bulleted rewrite was attempted and reverted because `convert`'s residual-goal order
there is unstable, which is exactly what the `all_goals first` form absorbs; and
`WittAlgebraCohomology`'s `convert …; all_goals norm_num` (harmless, cocycle-adjacent).

A tactic-robustness finding worth recording: in this Mathlib version a failing `ring`
falls back to `ring_nf` and *succeeds without closing the goal*, so
`first | ring | tac` never reaches `tac`. Fallback chains must put `ring` last
(the new proofs use `first | (exfalso; omega) | ring`).

### B4. ✅ Golf duplicated `hw_apply_*` boilerplate

`HeisenbergAlgebra.hw_apply_kgen/jzero` and `VirasoroAlgebra.hw_apply_cgen/lzero`
(four copies of a 10-line `Basis.constr_apply_fintype` + `Finset.sum_eq_single`
computation) are now two lines each via `Basis.constr_basis`
(excluding `Basis.constr_apply_fintype` from the simp set, which otherwise fires

### B6. ✅ Junk-import cleanup

Imports that were clearly artifacts of import-minimization tooling were replaced by
the real dependencies (verified by full builds):

* `CentralChargeCalc.lean`: `Mathlib.RingTheory.Henselian` et al. → `import Mathlib`
  (matching the exemplar and `Sugawara.lean`, its only consumer);
* `VirasoroCocycle.lean`: `Mathlib.Algebra.Azumaya.Basic`,
  `Mathlib.GroupTheory.MonoidLocalization.Basic`, normed-ring/star imports → none
  (its two project imports suffice); the two Mathlib facts downstream
  `WittAlgebraCohomology.lean` was silently absorbing through them
  (`field_simp`, `Module.rank` + the free-module instance for vector spaces) are now
  imported *there*, where they are used;
* `IndexTri.lean`: normed/star/order imports → `Data.Sign.Defs`, `Data.Set.Lattice`,
  `Tactic.Linarith`;
* `VermaModule.lean`, `LieAlgebraModuleUEA.lean`: dropped
  `Mathlib.Order.CompletePartialOrder`.

### B7. ✅ Silence pre-existing structural warnings (kept-as-is zone, mechanical only)

* `LieCohomologySmallDegree.lean`: the `AddCommGroup (LieTwoCocycle …)` instance
  re-declared `[LieAlgebra 𝕜 𝓰] [AddCommGroup 𝓪] [Module 𝕜 𝓪]` binders already in
  scope (an instance diamond in the making, per the new `overlappingInstances`
  linter); duplicates removed.
* `LieAlgebraModuleUEA.lean`: `moduleScalarOfModule` and
  `LieAlgebra.Representation.moduleUniversalEnvelopingAlgebra` marked `@[reducible]`

### B8. 💡 Proposed, not implemented (larger design changes)

* **Deduplicate `HeisenbergAlgebra.lean` ↔ `VirasoroAlgebra.lean`** (~150 parallel
  lines: `ext'`, instances, component lemmas, `ofCentral_apply`, the
  `Sum Unit ℤ ≃ Option ℤ` reindexing in `basisJK`/`basisLC`). A
  `LieTwoCocycle.CentralExtension.basisOption` helper would remove most of it, but
  it belongs to the central-extension area that is to be kept as-is; noted only.
* **Deduplicate `FockSpace.lean` ↔ `VirasoroVerma.lean`** (triangular-decomposition +
  two-element-cartan boilerplate). Worthwhile if a third algebra is added; after the
  B3/B4 golf the duplication is ~40 lines per file, so it was left readable-as-is.
* **`WittAlgebra.bracket_self`**'s `[NoZeroSMulDivisors 𝕜 (WittAlgebra 𝕜)]`
  hypothesis: deliberate `CommRing`-generality; kept.
* **`@[fun_prop]` tagging** of the `hasFiniteSupport_*` lemmas would let the
  `finsum_add_distrib ?_ ?_` side goals close by `fun_prop`; explicit terms were kept
  (fermionic style) since they document which support fact each step uses.
* **`ofCentral_apply`'s `change …; aesop`** (pre-bump code): works, mildly opaque;
  left alone.
