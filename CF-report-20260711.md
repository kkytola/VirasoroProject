# VirasoroProject improvement analysis and implementation report

*Date: 2026-07-11. Baseline: commit `f1b6807` (Lean `v4.32.0-rc1`, Mathlib `052559c`), full build green.*

This report analyzes how the formalization could be improved — design, structure,
maintainability against toolchain bumps, and proof readability (with a preference for
`calc` blocks) — and tracks which improvements were actually implemented. The comparison
repository `/opt/HL/MLP/MyLeanPlay/` (two fermionic Sugawara constructions, Ramond and
Neveu-Schwarz sectors) serves as the exemplar: its files were written against current
Mathlib idioms and are markedly more robust and readable than the bosonic
`Sugawara.lean` here.

Per instructions, the Lie-cocycle/central-extension development
(`LieCohomologySmallDegree.lean`, `CentralExtension.lean`, `IsCentralExtension.lean`,
`SectionSES.lean`) is kept essentially as-is; only mechanical warts introduced by the
version bump are polished there.

**Status legend:** ✅ implemented · 🔶 partially implemented · 💡 proposed, not implemented.

---

## A. The Sugawara construction (`Sugawara.lean`, `CentralChargeCalc.lean`)

This is where the gap to the exemplar is largest. The fermionic files prove the *same
shape* of theorem (`[Lₙ, Lₘ] = (n−m)L_{n+m} + δ_{n+m,0}·(c/12)(n³−n)·1`) via a chain of
five focused lemmas, each with a `calc` skeleton, while the bosonic file proves it in
one ~175-line monolith (`commutator_sugawaraGen`, lines 505–680) with five levels of
nested `by_cases`, inline index gymnastics through `Finset.sum_of_injOn` with `toNat`
/ `natAbs` conversions, and side conditions interleaved with the main argument.

### A1. ✅ Adopt `Function.HasFiniteSupport` and its combinator API

Mathlib (2026, M. Stoll) now has `Function.HasFiniteSupport f := f.support.Finite`
with combinators `.smul_right`, `.smul_left`, `.add`, `.neg`, `.fun_comp`,
`.comp_of_injective`, … and `finsum_add_distrib` / `finsum_sub_distrib` /
`smul_finsum'` / `finsum_smul'` take it directly. The bosonic file predates this and
carries **eight** near-duplicate `finite_support_*` lemmas (`…_apply`, `…_apply₀`,
`smul_…`, `pairNO` vs `pairNO'` variants), each proved from scratch. The fermionic
files get by with **four** one-line corollaries of a single lemma.

Implemented: one support lemma `hasFiniteSupport_pairNO_apply` (general index pattern
`(m−k, n+k)`), everything else derived via combinators. The blueprint reference
`finite_support_smul_pairNO_heiOper_apply` is renamed accordingly
(`hasFiniteSupport_smul_pairNO_apply`) and `blueprint/src/chapters/sugawara.tex`
updated.

### A2. ✅ Normal-form lemma `pairNO' = product − boundary·1`

The single most consequential structural idea in the fermionic files is
`ferPairNO_eq_sub_smul_one_sign`: the normal-ordered pair equals the *raw* product
minus an explicit scalar multiple of `1` supported on the antidiagonal. All commutator
manipulations then happen on raw products (where `commutator_pair'`-style identities
apply), and the boundary terms are carried along as explicit scalars.

Bosonic analogue (new lemma `pairNO'_eq_mul_sub_boundary_smul_one`):

```
:J k J l:' = J k * J l − (if 0 ≤ k ∧ k + l = 0 then (k : 𝕜) else 0) • 1
```

This replaces the previous approach where `commutator_sugawaraGen_heiPairNO'` was
proved by a 65-line four-way case split on the signs of `k` and `n+k`, re-deriving the
commutation relation inside each branch.

### A3. ✅ Restate `commutator_sugawaraGen_heiPairNO'` in the blueprint's form

The blueprint (`lem:CommutatorSugawaraNormalOrderedPair`) states

```
[Lₙ, :J_k J_{m−k}:] = −k :J_{n+k} J_{m−k}: − (m−k) :J_k J_{n+m−k}:
                      + (n+k) δ_{n+m,0} (𝟙[−n ≤ k < 0] − 𝟙[0 ≤ k < −n]) id
```

— a *cleaner* statement than the Lean lemma had (there, the `δ`-terms sat *inside* a
`−k •` scalar action, which forced every downstream user to re-distribute them). The
Lean statement now matches the blueprint: NO-part with plain coefficients plus a
single `(if n + m = 0 then boundary k else 0) • 1` term. Proved from A2 in a few
lines instead of 65.

### A4. ✅ Split the main proof into the fermionic file's structure

`commutator_sugawaraGen` is now assembled from:

1. `commutator_sugawaraGen_apply_eq_finsum_commutator_apply` (kept, blueprint name) —
   commutator–finsum interchange, now a `calc`.
2. `commutator_sugawaraGen_heiPairNO'` (A3) — the per-term normal form.
3. `sugawaraGen_NO_sum` (new, `private`) — the `∑ᶠ` telescoping/index-shift
   computation `∑ᶠ k (−k·NO₁ − (m−k)·NO₂) = (n−m) • ∑ᶠ NO`, written as a commented
   `calc` block with the index shift done by `finsum_comp_equiv (Equiv.subRight n)`
   and side conditions collected after the `calc` (exactly the Ramond
   `sugawaraGen_NO_sum` pattern).
4. `ccTermInt` + `support_ccTermInt_subset_Icc` + `sugawaraGen_cc_sum` (new,
   `private`) — the central-charge sum in closed form via `sum_Ico_quadratic`
   (see A5), handling both sign regimes *without* `toNat`/`natAbs` reindexing.
5. The main theorem, whose body is now: expand, rewrite with (2), split
   `n + m = 0` or not, and close with (3), (4).

The old proof's `smul_cancel_of_non_zero_divisor`-by-2 trick, the anonymous
`⟨fun k ↦ k − n, …⟩` equivalences (now `Equiv.subRight`/`Equiv.addRight`), and the
`Finset.sum_of_injOn` reindexings are all gone.

### A5. ✅ Replace the `zPrimitive` machinery by Gauss-sum closed forms

`CentralChargeCalc.lean` (234 lines) built a discrete-integration theory
(`zPrimitive`, `zMonomialF` with five evaluation lemmas at degrees 0–5, and a
factorial-product formula) to evaluate one quadratic sum. MyLeanPlay's
`GaussSums.lean` (69 lines) does the same job with three lemmas —
`sum_Ico_id`, `sum_Ico_sq`, `sum_Ico_quadratic` over `Finset.Ico a b`, `a b : ℤ` —
valid in both sign regimes, which is exactly what the central-charge computation
needs.

Implemented: `CentralChargeCalc.lean` rewritten with the three Gauss-sum lemmas
(ported from MyLeanPlay); `bosonic_sugawara_cc_calc_nonneg` (referenced by the
blueprint) kept with its exact statement, now a two-line corollary. The
`zPrimitive`/`zMonomialF` theory is deleted — it was used nowhere else. (If discrete
integration is wanted again later, it is one `git revert` away, or better,
MyLeanPlay-style Gauss sums generalize.)

### A6. ✅ Make `representationOfCentralChargeOfL` bump-proof

The definition used a tactic-mode `let ops : Option ℤ → _ := fun n' ↦ match n' with …`
inside `by apply`; the companion lemmas then had to *reconstruct that match-term
verbatim* inside `show`/`convert` — precisely the pattern that broke during the bump
(the repair needed `show` with the full match expression, and `unfold` in three
downstream lemmas). Implemented:

* the operator family is `fun i ↦ i.elim (c • 1) lOper` (an `Option.elim`, no match
  syntax to reconstruct);
* the definition is term-mode `LieAlgebra.representationOfBasis … <| by …`;
* new `@[simp]` lemma `representationOfBasis_apply_basis` in
  `LieAlgebraRepresentationOfBasis.lean`, so `…_cgen` / `…_lgen` are `simp`-level
  consequences and downstream files never `unfold` the definition;
* `sugawaraRepresentation_cgen` / `sugawaraRepresentation_lgen_apply'` and the
  `FockSpaceSugawara.lean` consumers rewritten accordingly (the `unfold …; convert ..`
  repairs are gone).

### A7. ✅ Drop the project-local `LinearMap.map_finsum`

`ToMathlib/Topology/Algebra/Module/LinearMap/Defs.lean` existed to provide
`LinearMap.map_finsum`; Mathlib's `map_finsum` (any `AddMonoidHomClass`) covers it
(MyLeanPlay already notes this and deleted its copy). File deleted, `Sugawara.lean`
uses `map_finsum`.

### A8. 💡 Not done: unify `pairNO`/`pairNO'` into a single definition

One could define only `pairNO'` (sign-based ordering) and keep `pairNO` as a lemma.
Both the blueprint and the API treat `pairNO` (index-comparison ordering) as *the*
definition with `pairNO'` as the computationally convenient form, and both names are
blueprint-pinned. The two-definition design is defensible (it isolates where `heiComm`
is genuinely needed), so this was left alone.

## B. Repository-wide improvements

### B1. ✅ Sync `Commutator.lean` with the MyLeanPlay superset

MyLeanPlay's `Commutator.lean` is a strict superset (adds `add_commutator`,
`commutator_add`, `smul_commutator`, `commutator_smul`). The file is now synced; the
added lemmas are used by the Sugawara refactor. (Keeping the two repos' shared files
textually identical also makes future diffing trivial.)

### B2. ✅ Delete dead `ToMathlib` files

Five files were imported by nothing and are not even part of the default build
target (so they silently rot — none of them were fixed during the bump):

* `ToMathlib/Topology/Algebra/BigOperators/FinProd.lean` — a stale copy of a file
  MyLeanPlay maintains (and marks "currently unused, upstreaming candidates");
* `ToMathlib/LinearAlgebra/Finsupp/Supported.lean` — *duplicates* `finsum_mem_span` /
  `finsum_mem_mem_span`, which live (and are used) in
  `ToMathlib/LinearAlgebra/Basis/FinsumRepr.lean`;
* `ToMathlib/Topology/Algebra/ConstMulAction.lean`,
  `ToMathlib/Topology/Algebra/InfiniteSum/Basic.lean`, `ToMathlib/Topology/Order.lean`
  — remnants of an abandoned discrete-topology-summability approach.

All five deleted (git history preserves them). `A7` deletes a sixth.

### B3. ✅ Golf the bump-repair scars

The bump commit (`f1b6807`, "possibly dubious proof repairs") left recognizable
scars; each is now replaced by an honest proof:

* **`all_goals first | rfl | simp […] | simp […]`** (with a *duplicated* branch) in
  `FockSpace.lean` / `VirasoroVerma.lean` cartan-basis lemmas — replaced by proofs
  that state the needed defeq step with `show`/`Subtype.ext` and close each `convert`
  residual explicitly.
* **`convert key v using 1; all_goals first | rfl | (by_cases …)`** in
  `FockSpaceSugawara.lean` (`commutator_lsmul_jgen_…`) — restructured with `ext` +
  named case analysis.
* **`apply ext' <;> simp […] <;> rfl`** in `HeisenbergAlgebra.lie_jgen` /
  `VirasoroAlgebra.lgen_bracket` — non-terminal `simp` followed by `rfl` is fragile;
  restructured to `ext'` first, then per-component computation.
* **`unfold sugawaraRepresentation…`** in `Sugawara.lean` / `FockSpaceSugawara.lean` —
  eliminated by A6's `@[simp]` API.
* **`:= by exact …`** wrappers on `toAbelianLieAlgebraOn`, `ofCentral`,
  `toWittAlgebra` — kept where genuinely needed for the type-synonym defeq (with a
  comment), removed where not. These stem from `HeisenbergAlgebra`/`VirasoroAlgebra`
  being `def`-opaque synonyms of `LieTwoCocycle.CentralExtension …`; that opacity is
  a deliberate design choice and is kept.
* **`simp; ring` / `all_goals norm_num` closers** left by the bump in
  `Sugawara.lean:678`, `WittAlgebraCohomology.lean:144` — tightened.

### B4. ✅ Golf duplicated `hw_apply_*` boilerplate

`HeisenbergAlgebra.hw_apply_kgen/jzero` and `VirasoroAlgebra.hw_apply_cgen/lzero`
each unfolded `Basis.constr_apply_fintype` into a `Finset.sum_eq_single` computation
(~10 lines each, four copies). They are one `Basis.constr_basis` rewrite each.

### B5. ✅ `ChargedFockSpace.eventually_jgen_smul_eq_zero`: `calc` instead of `rw`-chain

The proof carried a `-- calcify?` comment. It is now the intended `calc`
(`J_k • v = J_k a • Ω = a J_k • Ω = a • 0 = 0`), which is also the proof the
blueprint describes in words.

### B6. ✅ Remove leftover scratch and junk imports

* Stray `example (R U V W : Type) … := by exact β.flip` in `HeisenbergAlgebra.lean`
  (leftover exploration) — deleted.
* Junk imports (apparently from an import-minimization tool picking bizarre
  transitive parents): `Mathlib.RingTheory.Henselian` in `CentralChargeCalc.lean`,
  `Mathlib.Algebra.Azumaya.Basic` + `Mathlib.GroupTheory.MonoidLocalization.Basic` +
  normed-ring imports in `VirasoroCocycle.lean`, normed/star imports in
  `IndexTri.lean` — replaced by the minimal actual dependencies (verified by build).
* `VirasoroProject.lean` root now also imports `CentralChargeCalc` and `Commutator`
  explicitly so every live file is reachable from the root module.

### B7. ✅ Silence pre-existing structural warnings (kept-as-is zone, mechanical only)

* `LieCohomologySmallDegree.lean:261` "overlapping instance parameters" — the
  `instAddCommGroup` instance declared `[AddCommGroup 𝓪]`, `[Module 𝕜 𝓪]`,
  `[LieAlgebra 𝕜 𝓰]` binders that duplicate ones already in scope; duplicates
  removed (no mathematical change).
* `LieAlgebraModuleUEA.lean` "definition of class type must be `@[reducible]`" —
  `moduleScalarOfModule` and `moduleUniversalEnvelopingAlgebra` marked
  `@[reducible]` per the linter.

### B8. 💡 Proposed, not implemented (larger design changes, listed for consideration)

* **Deduplicate `HeisenbergAlgebra.lean` ↔ `VirasoroAlgebra.lean`** (~150 shared
  lines: `ext'`, instances, `bracket/add/smul_fst/snd`, `ofCentral_apply`, the
  `Sum Unit ℤ ≃ Option ℤ` reindexing in `basisJK`/`basisLC`). A helper
  `LieTwoCocycle.CentralExtension.basisOption` + generic `fst/snd` simp lemmas would
  remove most of it — but it lives in the central-extension area that is to be kept
  as-is, so only noted here.
* **Deduplicate `FockSpace.lean` ↔ `VirasoroVerma.lean`** (triangular decomposition +
  two-element-cartan boilerplate). A parametrized "rank-2 cartan of an
  `ofBasis`-triangular decomposition" mini-API would halve both files. Worthwhile if
  a third algebra is added; not done now to keep the diff reviewable.
* **`WittAlgebra.bracket_self`** requires `[NoZeroSMulDivisors 𝕜 (WittAlgebra 𝕜)]`
  because the file works over a `CommRing`. All uses are over fields where this is
  automatic; the generality could be dropped for simplicity, but it is harmless and
  deliberate, so kept.
* **`fun_prop` for support side-goals**: the new `HasFiniteSupport` lemmas could be
  `@[fun_prop]`-tagged so `finsum_add_distrib ?_ ?_` side conditions close by
  `fun_prop`. Left as a follow-up since explicit terms (fermionic style) document
  *which* support fact is used.

## C. Constraints respected

* **Blueprint/`checkdecls`**: `blueprint/lean_decls` is generated from `\lean{…}`
  macros in `blueprint/src/chapters/*.tex` at CI time. All pinned names were kept,
  except `finite_support_smul_pairNO_heiOper_apply` →
  `hasFiniteSupport_smul_pairNO_apply` (TeX updated in the same change). All other
  Sugawara-chapter names (`pairNO`, `pairNO_apply_eq_zero`,
  `heiOper_pairNO_eq_pairNO'`, `sugawaraGen`,
  `commutator_sugawaraGen_apply_eq_finsum_commutator_apply`,
  `commutator_sugawaraGen_heiOper`, `commutator_sugawaraGen_heiPairNO'`,
  `bosonic_sugawara_cc_calc_nonneg`, `commutator_sugawaraGen`,
  `sugawaraRepresentation`) resolve with unchanged (or blueprint-*matching*)
  statements.
* **Cocycles / central extensions**: no design changes in
  `LieCohomologySmallDegree.lean`, `CentralExtension.lean`, `IsCentralExtension.lean`,
  `SectionSES.lean` — only the mechanical items in B7 and none of the bump repairs
  there were reverted (they were already of the robust `show`-based style).
